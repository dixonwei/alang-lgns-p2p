# LGNS HTLC 合约说明

## 状态

- 源码：`LGNSHTLC.sol`
- 当前状态：**未编译验证、未部署、未审计**
- 不能因为仓库里有这份源码，就认为真实资金已经受到保护。
- 必须先在测试环境完成小额锁仓、领取、超时退款测试，再部署到主网。

## 作用

同一份合约分别部署到 Polygon 和 ANUBIS 链：

- 卖方在源链锁定 LGNS；
- 买方在目标链锁定对应 LGNS；
- 双方使用同一个哈希锁；
- 一方公开密钥后，另一方用同一密钥领取另一条链的资产；
- 未完成时，锁币方在超时后取回资产；
- 平台不托管资产。

## 固定规则

- 平台服务费：`300 BPS = 3%`
- 费率写在合约常量中，管理员不能修改；
- 手续费地址在部署时固定，建议使用 2-of-3 多签；
- 管理员没有直接提取用户锁仓资产的函数；
- 退款只能由原锁币钱包在超时后发起；
- 支持带转账税的 ERC20：按合约实际收到的余额记账。

## 费用方向

合约的 `feeOnClaim` 参数用于区分：

- `true`：该笔是卖方收款，领取时扣 3%；
- `false`：该笔是买方收回本金，不扣 3%。

一套完整 P2P 交换中，只应在卖方收款的那一侧设为 `true`。`feeOnClaim` 必须由正式订单注册表或平台签名条款强制校验，不能只依赖前端传入，否则卖方可以绕过 3% 服务费。当前源码只是 HTLC 基础原件，不能直接当作完整业务合约上线。

## 双链时间设置建议

- 卖方源链锁仓：60 分钟；
- 买方目标链锁仓：30 分钟；
- 卖方先领取目标链，公开密钥；
- 买方必须在源链 60 分钟到期前领取。

时间不能超过订单页面允许的最长 24 小时。

## 正式部署前检查

1. 确认 Anubis 和 Polygon 的 LGNS 合约均允许转入 HTLC 合约；
2. 实测钱包转合约、合约转钱包的代币税；
3. 验证 `amount` 与合约实际收到的余额差异；
4. 测试成功领取；
5. 测试超时退款；
6. 测试错误密钥不能领取；
7. 测试重复领取和重复退款；
8. 测试合约中的手续费实际到账；
9. 完成独立审计；
10. 在小额真实交易中连续运行后再扩大额度。
